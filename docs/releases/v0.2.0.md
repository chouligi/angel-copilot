# Angel Copilot v0.2.0 — release preparation

Status: prepared locally; not tagged or published.

## Release notes

Angel Copilot now gives one action recommendation: **INVEST / PURSUE / WAIT / PASS**. INVEST means the evidence and terms support a normal cheque now. PURSUE means prioritize diligence. WAIT means defer active work until a named trigger. PASS means stop at the current terms or for this investor. Reports no longer ask users to select a screening or commitment mode or present two verdicts.

Every assessment starts with a plain-language company overview. The Decision Brief prominently displays a weighted average over scored factors, score coverage (with genuinely unassessable factors excluded, not treated as zero), pursuit priority, attention and readiness. Factors receive stage-appropriate provisional scores when the business model provides a reasonable basis; routine gaps in pitch materials alone neither leave scores blank nor lower them. Chat and generated reports use the same structure and Evidence strength labels.

PURSUE requires a 3.5 / 5 weighted-score minimum and a deal-specific reason to prioritize diligence. Below 3.5, use WAIT at most; scores at or above 3.5 are eligible but do not automatically trigger PURSUE. INVEST requires sufficient diligence, understood and attractive net economics, investor fit and justified cheque sizing.

Economic sensitivities can use supported ranges without inventing exit probabilities or requiring a personal cheque size. Diligence separates verification work, accepted venture risks and future business milestones. Missing private information alone does not force WAIT when the deal merits investigation; the report identifies when to pursue work now and when to wait for a stated trigger.

### Compatibility

- New assessments use schema version 4 and one action recommendation; the batch CLI has no assessment mode selector.
- Existing schema version 1/2/3 files remain readable with their original recommendation meanings; report regeneration does not remap archived labels.
- Saved assessments without the new company-summary field display their recorded product/customer descriptions.
- Python distribution and packaged skill are version 0.2.0. This is separate from assessment schema version 4 and reporting-contract version 4.

## Assets

- `dist/angel-copilot-v0.2.0.skill`: current skill instructions and references.
- `dist/angelcopilot-0.2.0-py3-none-any.whl`: local batch CLI.
- `dist/angelcopilot-0.2.0.tar.gz`: Python source distribution.
- `dist/SHA256SUMS`: checksums for these three assets.

The repository-root `angel-copilot.skill` must match the versioned skill asset. The Python distributions contain the CLI; install the skill separately.

## Build and publish checklist

1. Review and commit all intended framework, reporting, documentation, tests and sample-output changes. Untracked files do not enter a release unless committed.
2. Run `./scripts/build_skill_package.sh` and `./scripts/verify_skill_package.sh`.
3. Run `uv build` and copy `angel-copilot.skill` to `dist/angel-copilot-v0.2.0.skill`; regenerate `dist/SHA256SUMS`.
4. Change the changelog entry from Unreleased to the actual publication date; commit that change and ensure the intended release changes are committed.
5. Tag that commit `v0.2.0` and push the commit and tag.
6. Publish the GitHub release using the notes above and attach all four assets. Building or updating a local installed skill does not update an existing GitHub release.

Prepared assets represent the current working tree. Rebuild if any source changes before publishing.
